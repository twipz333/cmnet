# Dota 2 Draft Advisor (`advisor`)

Локальный инструмент-советник по фазе пиков/банов в Dota 2: предсказывает намерения врага
и рекомендует лучшие пики/баны. Один статический бинарь под Windows, без DLL и внешних
рантаймов.

> Полное ТЗ — в [`CLAUDE.md`](./CLAUDE.md). План разработки — в `.omc/plans/`.

## Ожидания по точности

Это **советник, а не оракул**. Потолок предсказания победы по чистому драфту — ~0.60–0.65
ROC AUC. Ценность инструмента — мета-осознанные подсказки пик/бан и предугадывание
комфорт-пиков врага, **не** точное предсказание исхода. На свежем патче с малым объёмом
данных точность ниже — это ожидаемо.

## Запуск (единый TUI)

Главный сценарий — один бинарь, всё из TUI:

```sh
advisor --gsi --token <STRATZ_TOKEN>
```

Открывается home-экран с действиями: **Scan draft** (живой советник), **Scout opponents**
(фетч+заморозка снапшота), **Sync data** (нужен `--token`), **Train model**. `esc` —
назад в меню. Подкоманды (`sync`/`train`/`serve`/`scout`/`gsi-install`/`gsi-probe`) остаются для
скриптинга.

### Фоновый сбор данных

Пока `advisor` открыт, он **сам** подкачивает матчи и переобучает модель — руками
запускать `sync` не нужно. Статус видно в строке под меню (в web — в статус-баре):
идёт сбор, обучение, пауза или когда следующий проход.

Так сделано потому, что корпус физически не набирается за один запуск: STRATZ отдаёт
лишь ~30% публичных матчей, потолок ~3000 драфтов в сутки, дальше +270/день на
поддержание. Долгая команда на переднем плане для такого не годится — один неудачный
ответ OpenDota Explorer заканчивал сбор с кодом выхода 0 и почти пустым результатом.

Как это переживает внезапное завершение:

- проходы **короткие** (по умолчанию 250 public-CM драфтов), а граница прохода — это
  чекпоинт: watermark'и пишутся в SQLite, поэтому убитый посреди прохода advisor теряет
  только недокачанное, а следующий запуск продолжает с того же места;
- банд, который Explorer не отдаёт, **переспрашивается** с паузами (30 с, 2 мин), а если
  так и не ответил — пропускается, но фронтир сбора **не** переносится ниже пропуска:
  дыра достанется следующему проходу, а не осиротеет;
- бандл пишется **атомарно** (temp + rename, предыдущий остаётся как `bundle.json.bak`),
  так что прерванное обучение не оставляет битый бандл, с которым `serve` не стартует;
- переобучение откладывается, пока открыт экран драфта: применение нового бандла
  пересобирает сессию, а это очистило бы доску между пиками;
- два запущенных `advisor` не собирают в один кэш вдвоём (общая дневная квота STRATZ) —
  второй поднимается с UI, но без фонового сбора и говорит об этом.

Ручные `Sync`/`Train` имеют приоритет: фоновый проход на это время отменяется и
возобновляется сам. Скаут фон не останавливает.

Настройки — в секции `advisor:` конфига (`auto`, `auto-public-cm`, `auto-train-every`,
`auto-train-min-new`, `auto-idle`, `auto-max-idle`) или флагами; выключается `--auto=false`.
`auto-public-cm` требует токен: без него детали матча идут через OpenDota `/matches/{id}`,
который отваливается по таймауту примерно в 9 случаях из 10.

## Подкоманды

| Команда | Назначение |
|---|---|
| `advisor sync` | Инкрементальная подкачка CM-матчей в локальный кэш (SQLite). |
| `advisor train` | Обучение моделей из кэша → версионированный **бандл**. |
| `advisor serve` | Режим советника: рекомендатор + TUI, только экран драфта (это запускают друзья). |
| `advisor scout` | Фетч и заморозка снапшота оппонентов (слои 2–3). |
| `advisor gsi-install` | Установка GSI-конфига для живого ввода состояния драфта. |
| `advisor gsi-probe` | Диагностический захват сырых GSI payload'ов (см. [docs/gsi-probe.md](./docs/gsi-probe.md)). |
| `advisor log` | Чтение локального лога решений: что советовали, что выбрали, почему не по совету. |

## Web-UI (браузерный фронт)

```sh
advisor                                  # web UI по умолчанию (URL в терминал)
advisor --open                           # то же + открыть вкладку в браузере
advisor --tui                            # классический терминальный home
advisor --web-addr 127.0.0.1:54000
```

**`advisor` без флагов — единственный вход в браузерный фронт.** У `serve` отдельного
web-режима нет намеренно: там пустой `ShellConfig`, поэтому вкладки Данные/Разведка/Статистика
оказывались молча серыми и скаутить было нечем. Один режим вместо двух — не бывает
экрана, который выглядит рабочим, но ничего не делает.

Полный аналог терминального home-экрана (`advisor --tui`), четыре вкладки:

| Вкладка | Что внутри |
|---|---|
| **Драфт** | доска, рекомендации, предикт врага, **«не бойся»**, мета по позициям, сила драфта, таймеры объектов, матчапы по клику на героя, добавление врага на лету |
| **Данные** | `Sync` (подкачка матчей в кэш) и `Train` (переобучение → бандл) с живым логом прогресса и отменой, плюс **картина кэша** (см. ниже) |
| **Разведка** | скаут врагов и союзников (слои 2–3) |
| **Статистика** | скаученные игроки с комфортками и удалением, счётчик драфтов ивента (слой 3) с очисткой, редактор пула героев, редактор правил советов (#10) |

Долгие операции стримят прогресс построчно и отменяются кнопкой. После `Train` или
скаута драфт-экран сам перечитывает бандл и снапшот — рестарт не нужен. Одновременно
идёт только одна операция, вторая отбивается (как и в TUI).

### Картина кэша (вкладка «Данные»)

Под кнопками — что именно накоплено, графиками (`/api/corpus`, считается по запросу,
не на каждый poll):

- **Плитки**: матчей всего, из них **CM-драфтов** (с бан-фазой — только на них учится
  предикт врага, и это единицы процентов кэша), сколько матчей с известными позициями
  игроков, объём драфт-действий.
- **Матчи по дате игры** — чем покрыто окно обучения: провал значит, что за этот день
  мета известна хуже.
- **Загружено в кэш по дням** — когда данные реально скачивались; пустой день здесь
  значит, что advisor в этот день не был запущен. **Это разные графики и они выглядят
  по-разному**: один проход sync тянет матчи, сыгранные за несколько недель.
- **Откуда данные** — доли `bulk` / `public-cm` / `pro` (разные популяции, не смешивать).
- **Ранги собранного** — распределение по медалям и доля матчей с неизвестным рангом
  (их фильтр обучения намеренно не выбрасывает).
- **Мета в собранных данных** — самые пикаемые и самые баненые герои: сырая частота,
  удобно как проверка, что собралось именно то, что ожидалось.

У каждого графика есть «Показать таблицей» — те же числа текстом, значения также
видны при наведении и с клавиатуры. Палитра подобрана под тёмный фон и проверена на
различимость при дальтонизме.

Состояние приезжает по SSE, поэтому при `--gsi` страница обновляется сама, без
перезагрузки. В GSI-режиме доска только для чтения (её ведёт Dota) — это написано
прямо на экране, а не выражено серыми кнопками. Скаут врага на лету, фильтр героев и
матчапы по клику при этом работают: доску они не меняют.

Фронт — статика, вшитая в бинарь через `go:embed`: никакого `npm`, никакого CDN,
`go build` остаётся единственной командой сборки. Слушает только loopback; cross-site
POST'ы отбиваются по `Sec-Fetch-Site`.

> Web и TUI — два View над одним ядром (`internal/session`). Ничего не считают сами и
> ничего не пересортировывают: ранжирование уже округлено и разрешено по `hero_id` на
> стороне ядра (§6), поэтому оба показывают идентичный результат.

## Сборка

```sh
# статический бинарь под Windows (без CGO)
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -o advisor.exe ./cmd/advisor
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -o advisor-discord.exe ./cmd/advisor-discord
```

## Живой ввод драфта (GSI)

```sh
advisor gsi-install                      # положит cfg в папку Dota (автодетект пути)
advisor serve --gsi --side radiant       # поднимет локальный HTTP, читает состояние из Dota
```

`gsi-install` пишет `gamestate_integration_advisor.cfg` в
`.../dota 2 beta/game/dota/cfg/gamestate_integration/`. Без `--gsi` `serve` работает на
ручном вводе (выбор героев из списка с фильтрацией).

> Надёжность GSI по `account_id` врагов во время драфта не гарантирована — это проверяется
> экспериментально (см. §12 ТЗ). Парсер блока драфта толерантен к вариантам схемы
> (`radiant`/`dire` либо `team2`/`team3`).

## Скаут оппонентов (резолв вручную)

```sh
advisor scout --player https://www.opendota.com/players/123456789 \
              --player 76561198083722517 \
              --player "[U:1:200000]"
```

`scout` резолвит `account_id` из сырого id, SteamID3/64 или ссылки на профиль
(OpenDota / STRATZ / Dotabuff / Steam) — удобно, когда игрока нашли руками. Достаточно
**одного** резолвнутого id из пяти (§9): через него находится матч команды → весь драфт.

Затем фетчит **слой 2** (affinity игроков, окно ~месяц) и **слой 3** (драфты команды в
текущем ивенте) и замораживает в `snapshot.json`. Раздай файл тиммейтам и запускай
`advisor serve --gsi --snapshot snapshot.json` — предикт врага блендится лог-линейно
(`score = logP1 + w2·log aff2 + w3_eff·log aff3`), вес слоя 3 крепнет по ходу сетки.
Предсказания с меткой `●event` вытянуты слоем 3. Win-prob для своих пиков остаётся на
слое 1. Нет данных → graceful degradation к 1+2 или чистой мете.

## Панель «не бойся»

Список банов отвечает на вопрос «что забрать у врага», но не на вопрос «что можно
отдать» — а под таймером драфта именно второй вопрос жжёт баны впустую. Поэтому рядом
с предиктом врага показывается обратный список: герои, которых враг с большой
вероятностью возьмёт, но которые нашему драфту не опасны.

Опасность раскладывается на два числа, оба считает ядро (фронты ничего не вычисляют):
`threat` — насколько герой обыгрывает НАШИ текущие пики, `fit` — насколько он подходит
к драфту врага. Их взвешенная сумма (`danger`) — та же величина, по которой ранжируется
бан, так что «бань» и «не бойся» — два прочтения одной шкалы, а не два разных мнения.

Герой попадает в «не бойся», если его `danger` заметно ниже медианы по пулу вероятных
ходов врага, а не ниже какого-то абсолютного порога: что считать безобидным, зависит от
того, насколько страшна остальная доска. Без synergy/counter матриц панель пуста —
совет «не бойся» без данных под ним хуже отсутствия совета.

## Роли и игроки в кэше

Таблица `match_players` хранит участников матча: слот, `account_id`, героя, сторону и
лейновую позицию 1–5. Данные приезжают тем же запросом STRATZ, который синк и так делает
ради драфта, — дополнительных вызовов к API нет.

Правила записи:

- участники пишутся **только полным составом** 10/10 с уникальными слотами и героями;
  битый или обрезанный ответ оставляет матч без участников, но не портит выборку
  наполовину;
- анонимный профиль сохраняется как `NULL`, а не как `0` — иначе все скрытые профили
  кэша слились бы в одного несуществующего игрока;
- позиция, которую STRATZ не определил, остаётся `NULL` с пустым `pos_source`;
  агрегаты по ролям такие строки пропускают, а не сваливают в какую-нибудь позицию 5.

Матчи, закэшированные до появления таблицы, просто не имеют участников — ролевые фичи
деградируют по матчам, ресинк не требуется.

## Лог решений (что советовали и что вы выбрали)

Все офлайн-метрики проекта ретроспективны: они проверяют модель на драфтах, которые уже
сыграны людьми, не видевшими никаких рекомендаций. Сказать, полезен ли совет тому, кто
стоит у драфт-таймера, они не могут в принципе. Для этого и заведён лог: на каждый ваш шаг
он пишет доску, показанные рекомендации, предсказание ответа врага, выбранного героя и его
ранг в списке.

Самое ценное поле — **причина отказа**. Клавиша `r` в TUI (или панель «Почему не по совету»
в веб-UI) записывает свободным текстом, почему вы взяли не то, что советовали: «он это не
играет», «роль прочитана неверно», «рано раскрывать драфт». Именно из этих строк видно,
какого признака модели не хватает; из корпуса матчей это не выводится никак.

```sh
advisor log                       # сводка: доля принятых советов, причины отказа
advisor log --json --last 5       # последние пять драфтов как есть
advisor log --export shared.jsonl # копия для тиммейтов: id заменены псевдонимами
advisor log --forget 123456789    # стереть игрока из лога
advisor log --forget 123456789 --purge  # удалить драфты с ним целиком
```

Данные персональные, поэтому:

- файл `decisions.jsonl` лежит рядом с кэшем, права `0600`, **никуда не отправляется** и в
  раздаваемый снапшот не попадает;
- retention по умолчанию — 180 дней и 200 драфтов, применяется при каждом запуске;
- `Забыть игрока` в списке игроков теперь чистит и лог: id, ник, профиль и match_id
  вырезаются из всех записей, сами драфты остаются. Свободный текст причин при этом не
  трогается — программа не может надёжно определить, названо там имя или нет; если текст
  важен, есть `--purge`, который удаляет такие драфты целиком;
- в экспорте `account_id` заменяются псевдонимами с **новой случайной солью на каждый
  экспорт** — без соли такой «хэш» обращается перебором за секунды;
- выключается флагом `--decision-log=false`.

Доля принятых рекомендаций — **не** оценка качества модели: она растёт и от доверия, и от
усталости. Читать лог стоит ради причин отказа и ради возможности потом пересчитать те же
состояния новой моделью, имея зафиксированные профили «на тот момент».

## Качество данных и калибровка

`train` по умолчанию: **recency-веса** (свежие матчи весомее, half-life 30 дней),
**Platt-калибровка** win-prob (чтобы «65%» значило ~65%). 30 дней — компромисс,
выбранный по свипу на трёх скользящих окнах: предиктор вражеских пиков не различает
7/14/30 дней (победитель меняется от окна к окну), но заметно проседает совсем без
весов; win-prob на CM при переходе 7→30 дней нигде не падает (+0.018/+0.024/+0.004 по
окнам). Полный отказ от весов даёт по CM ещё чуть больше в двух окнах из трёх, но
портит предиктор везде — поэтому веса остаются. Это точечные оценки без парных
доверительных интервалов, так что соседние значения стоит считать равными.
Фильтры выборки:

```sh
advisor train --filter-patch 7.36 --min-avg-mmr 5000 --half-life 30
```

При добавлении героя/смене патча просто переобучаете (`train`) — выходной слой и hero
index map ресайзятся под актуальный список автоматически, друзьям раздаётся новый бандл.


## Discord remote-control

Отдельный процесс `advisor-discord.exe` (не вшит в advisor): slash-команды + озвучка
алертов рун/лотосов через [NTTS](https://ntts.fdev.team/docs) в войсе вызывающего.

1. В `config.yaml` advisor задайте `remote-token` (или флаг `--remote-token`).
2. Скопируйте `discord.yaml.example` → `discord.yaml`, заполните токены Discord/NTTS,
   `guild-id`, `role-id`, тот же `advisor-token`.
3. Clash Verge: PROXY для Discord и `ntts.fdev.team`; DIRECT для `127.0.0.1`.
4. Соберите оба бинаря в одну папку (`advisor.exe` и `advisor-discord.exe`).
   `advisor` сам поднимает Discord-бота **отдельным процессом** и гасит его при выходе.
   Вручную `advisor-discord.exe` запускать не нужно. Отключить: `--discord=false`.

```sh
advisor.exe --gsi
```

Команды (ответ ephemeral, только автору): `/scout`, `/scout-clear`, `/side`, `/lineup`,
`/voice join|leave`, `/status`, `/tts-reload`. Мутации идут в тот же session, что и web UI —
фронт обновляется по SSE. Текст/голос озвучки в `discord.yaml` → hot-reload без рестарта бота,
кэш в `tts-cache/`.

## Источники данных и атрибуция

Данные получаются из **STRATZ** (GraphQL) и **OpenDota** (REST). Использование STRATZ
требует атрибуции: *Powered by STRATZ — https://stratz.com*. Проект некоммерческий, для
личного/дружеского использования; ToS источников уважаются (Dotabuff/Dota2ProTracker не
скрейпятся).
